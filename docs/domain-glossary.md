# 领域词汇表 (Domain Glossary)

本词汇表定义了 `TTML ID Match v2` 项目核心架构中所使用的专业术语。

| 概念 (Term) | 说明 (Description) |
| :--- | :--- |
| **SourceAdapter** | 音乐平台适配器。封装了特定音乐提供商（如 Apple Music、Spotify 等）的接口集成，声明了稳定的平台 Key、上游依赖、检索逻辑及元数据写入行为。 |
| **SourceRegistry** | 适配器注册表。管理已验证的 `SourceAdapter` 集合及其依赖的有向无环图（DAG）。 |
| **MatchingEngine** | 匹配引擎。负责调度各平台适配器的并行或串行检索，管理全局并发预算、缓存、执行顺序以及部分服务故障的捕获与转换。 |
| **Candidate** | 匹配候选。各平台返回的结构化检索结果，对外暴露 ID、排位及解释性证据（Evidence），隐藏平台内部的数字评分。 |
| **Selection** | 用户选择。针对单个音频/TTML 组合，在各平台中选中的唯一候选 ID。 |
| **PairingPlan** | 文件配对方案。对用户上传的 TTML 和同名音频文件名进行确定性配对，并拦截配对冲突或命名歧义（如一歌多版本音频）。 |
| **PairPreview** | 单曲预览。呈现单个音频/TTML 配对的平台候选数据及默认写入变更方案（ChangePlan）。 |
| **PreviewSnapshot** | 预览快照。包含了文件哈希、元数据、检索候选及警告等信息的不可变 JSON 记录。这是后续生成变更方案和最终应用的唯一数据源，避免重复调用音乐平台。 |
| **ChangePlan** | 写入变更方案。表示即将应用于 TTML 的文本变更计划，包含输入/输出文件的 SHA-256 哈希、最终 TTML 文本以及元数据和语言的变更摘要。 |
| **SessionWorkflow** | 会话工作流。定义了用户进行文件上传、逐步预览、快照发布、方案应用、结果下载和会话删除等核心用例的业务边界。 |
| **SessionRepository** | 会话仓库。持久化存储版本化的会话/任务快照索引，并负责任务租约的生命周期管理。 |
| **ArtifactStore** | 物理存储介质。负责字节流与 JSON 数据实体（如上传文件、最终快照、生成的 TTML 结果等）的读写存储。 |
| **ReviewDraft** | 前端草稿。在快照成功提交后，在前端页面内临时维护的当前用户选择及应用载荷（Apply Payload）状态。 |
